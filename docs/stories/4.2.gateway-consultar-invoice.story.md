# Story 4.2 — Gateway: consultarInvoice + persistir vencimento na emissão

## Status
Ready for Review

## Story
**As a** sistema de conciliação,
**I want** consultar o status real de uma invoice na Cora e persistir o vencimento no momento da
emissão,
**so that** o webhook (4.3) possa confirmar o pagamento pela fonte da verdade e a baixa/aging tenham
a data de vencimento correta.

## Acceptance Criteria
1. `BoletoGatewayPort` ganha `consultarInvoice(idExterno): Promise<StatusInvoice>` com
   `StatusInvoice = { status: 'paid'|'canceled'|'open'|'overdue'|'unknown', valorPago: number | null, pagoEm: string | null }`.
2. `CoraGateway.consultarInvoice` faz `GET /invoices/{id}` via mTLS (reusa `obterToken` + `fetchMtls`),
   normaliza a resposta para `StatusInvoice`; erro/404 → `status: 'unknown'` sem lançar.
3. `MockGateway.consultarInvoice` retorna um `StatusInvoice` configurável (default `paid`).
4. Na emissão, o **`vencimento` resolvido** (due_date = hoje + diasVencimento) é **persistido** em
   `boletos.vencimento`: `criarBoleto` aceita `vencimento` e a rota de emissão passa a data.
5. Testes cobrem: `consultarInvoice` (paid/canceled/erro→unknown) com `https` mockado; emissão grava
   `vencimento`.
6. `typecheck`, `lint`, `test` verdes.

## Complexidade e Riscos
- **Complexidade:** M (~3 pontos). Extensão do gateway + pequeno ajuste na emissão.
- **Escopo OUT:** rota de webhook (4.3).
- **Riscos:** formato real da resposta do Cora (`GET /invoices/{id}`) não confirmado — *mitigação:*
  `normalizarStatusInvoice` isolado + teste de shape; ajustar só o normalizador quando a API existir.
- **DoD:** AC 1-6 + testes verdes + File List completa.
