# Story 10.4a — Cadastro de empresas e vínculo médico↔empresa

## Status
Ready

## Story
**As a** operador do sistema de cobrança,
**I want** cadastrar empresas (ex.: MEDISA) com dados de cobrança, conta emissora e regra de preço,
e vincular médicos a elas,
**so that** o sistema tenha a base de dados necessária para agregar produção por empresa nas
próximas stories (10.4b — execução agregada, 10.4c — emissão).

## Contexto
Primeira das 3 sub-stories em que a Story 10.4 foi quebrada pelo @architect (ver
`docs/stories/10.4.emissao-por-empresa-medisa.story.md` para o desenho completo e a justificativa
de reuso). Esta sub-story **só cria a base de dados e o cadastro** — nenhuma execução ou emissão
ainda. Sem ela, 10.4b/10.4c não têm onde buscar os dados da empresa.

**Reuso deliberado** (não reinventar): `DadosCobranca`, `CondicoesCobranca`, `ContaEmissora`,
`RegraPreco`/`RegraPrecoForma` (Story 10.1) são reaproveitados tal como estão — uma empresa usa
exatamente os mesmos tipos e as mesmas regras de validação que já existem para médico.

## Acceptance Criteria
1. **Tipos (`packages/shared`):** nova interface `Empresa` — `id`, `nome`, `cobranca: DadosCobranca
   | null` (reaproveita o tipo do médico — pagador PJ), `contaEmissora: ContaEmissora`,
   `condicoes: CondicoesCobranca | null`, `regraPreco: RegraPreco | null`, `ativo`, `createdAt`,
   `updatedAt`. Nenhum tipo reaproveitado é alterado.
2. **Vínculo:** `Medico` ganha `empresaGrupoId: string | null` (FK opcional para `empresas.id`).
   Backfill: todos os médicos existentes com `null` (nenhum comportamento muda). Este campo **não**
   substitui nada do médico — ele continua com `statusHapvida`, `modoCobranca`, etc., para a
   produção individual dele.
3. **Migration:** tabela `empresas` (colunas achatadas, mesmo padrão de `medicos` para
   cobrança/condições/regra de preço — reaproveitar literalmente os mesmos nomes de coluna
   `regra_preco_*` e a mesma CHECK de coerência por forma da migration 0025/0027, só que na tabela
   `empresas`); `medicos.empresa_grupo_id uuid null references empresas(id)`; tabela
   `empresas_historico` (mesmo padrão de `medicos_historico` — toda escrita em empresa gera
   histórico com autor e motivo, PRD §7).
4. **Zod:** `novaEmpresaSchema`/`atualizarEmpresaSchema` reaproveitando diretamente
   `dadosCobrancaSchema`, `condicoesCobrancaSchema`, `regraPrecoSchema` já existentes (não
   duplicar validação).
5. **Repository:** `empresa-repository.ts` — `criarEmpresa`, `listarEmpresas`, `buscarEmpresa`,
   `atualizarEmpresa` (com histórico, motivo obrigatório — mesmo padrão de `medico-repository.ts`).
6. **Rotas:** `GET/POST /api/empresas`, `GET/PATCH/DELETE /api/empresas/[id]`,
   `GET /api/empresas/[id]/historico` — mesmo padrão de auth (`requireRole(['admin'])` para
   escrita) e tratamento de erro das rotas de médico.
7. **UI:** `EmpresaForm.tsx` + `EmpresasManager.tsx` (nova tela em `/empresas` ou dentro de
   Configurações) reaproveitando os blocos de "Dados de cobrança" e "Regra de preço própria" já
   existentes em `MedicoForm.tsx` (extrair se fizer sentido, mas duplicar é aceitável se a extração
   inflar o escopo). `MedicoForm` ganha um campo opcional "Empresa de agrupamento (guias cardíacas)"
   — select das empresas ativas.
8. `npm run typecheck`, `lint`, `test` verdes; testes: Zod (cobrança PJ + regra de preço),
   mappers, repository (CRUD + histórico), componente básico do formulário.

## Complexidade e Riscos
- **Complexidade:** M (~5–6 pontos). É replicar padrões já existentes (médico) para uma entidade
  nova e mais simples (sem `statusHapvida`/`especialidade`/contagem de guias).
- **Escopo OUT:** execução agregada (10.4b); emissão de boleto por empresa (10.4c); qualquer
  cálculo de guias/valor — esta story só cadastra.
- **Riscos:**
  - Confundir `empresa_grupo_id` com `conta_emissora` (Épico 7) — são conceitos ortogonais, não
    reaproveitar a coluna existente (ver Dev Notes da 10.4 pai).
  - Regra de preço da empresa mal configurada não deve travar nada nesta story (só é USADA na
    10.4b) — validar coerência (Zod/CHECK) é suficiente aqui.
- **DoD:** AC 1–8 + testes verdes + File List completa.
