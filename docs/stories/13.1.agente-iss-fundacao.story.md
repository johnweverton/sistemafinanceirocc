# Story 13.1 — Fundação do agente de faturamento ISS: persistência e API com token dedicado

## Status
InReview — código e testes prontos; falta aplicar a migration 0054 e configurar o token (dono)

## Story
**As a** operador que fecha o faturamento dos clientes contábeis em `faixa_faturamento`,
**I want** que o sistema receba e guarde o faturamento lido do ISS Fortaleza por um agente local,
**so that** o diálogo de lote (Story 13.3) possa trazer o valor pronto para conferência, em vez de
eu buscar empresa por empresa no portal.

## Contexto
Épico 13 — arquitetura em `docs/architecture/feature-agente-faturamento-iss.md` (decisões G1–G4 do
dono, 2026-09-21). Esta story entrega só o lado servidor: banco, tipos, rotas do agente e a guarda
R5. O agente CLI é a 13.2; a UI é a 13.3.

## Acceptance Criteria
1. Migration `0061_agente_iss.sql`: tabelas `iss_execucoes_agente` e `iss_capturas` (append-only),
   colunas `origem` (`'manual' | 'iss_fortaleza'`, default `'manual'`) e `iss_captura_id` em
   `clientes_contabilidade_faturamentos`; RLS de leitura `has_profile()`, idempotente, com rollback.
2. `GET /api/integracoes/iss/alvos?competencia=AAAA-MM` devolve os clientes **ativos** em
   `faixa_faturamento` com documento (só dígitos), e lista à parte os sem documento.
3. `POST /api/integracoes/iss/execucoes` grava a execução, as capturas e as ciências. Totais são
   calculados no servidor. Cliente desconhecido, ou fora de `faixa_faturamento`, → 422 sem gravar nada.
   `status = 'capturado'` exige valor ≥ 0.
4. As duas rotas autenticam **só** por `Authorization: Bearer <AGENTE_ISS_TOKEN>`, comparado por
   SHA-256 em tempo constante com `AGENTE_ISS_TOKEN_SHA256`. Sem a env configurada → sempre 401
   (fail-closed). Ficam fora do gate de sessão do middleware.
5. Guarda R5: captura com competência ≥ 2026-11, valor 0 e faturamento lançado > 0 em alguma das
   3 competências anteriores recebe o alerta `possivel_nota_fora_escrituracao`.
6. Repositório expõe `listarPropostasIssVigentes(competencia)` (a captura mais recente por
   cliente) para a 13.3 consumir.
7. Nenhuma rota do agente escreve em `clientes_contabilidade_faturamentos` (G3).

## Dev Notes
- Token: gerar com `node -e "const c=require('crypto');const t=c.randomBytes(32).toString('hex');console.log('AGENTE_ISS_TOKEN='+t);console.log('AGENTE_ISS_TOKEN_SHA256='+c.createHash('sha256').update(t).digest('hex'))"`.
  O token vai só para o `.env` local do agente; na Vercel vai só o hash.
- Gravação não transacional (execução → capturas): se inserir as capturas falhar, a execução
  é apagada (compensação). O agente guarda o JSON localmente e pode reenviar.
