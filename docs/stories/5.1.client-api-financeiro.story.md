# Story 5.1 — Client da API real do Sistema Web + tipos do contrato + env

## Status
Ready for Review

## Story
**As a** desenvolvedor do sistema de cobrança,
**I want** um client de integração que fale o contrato REAL da API do Sistema Web
(`fin-clientes` → `fin-producoes` → `fin-itens`) com tipos próprios e variáveis de ambiente novas,
**so that** a sincronização de médicos (5.2), a contagem (5.3) e a execução por produção (5.5)
consumam a origem real por um único ponto, sem depender do contrato presumido do PRD §6.4.

## Acceptance Criteria
1. `packages/shared` ganha os tipos do contrato real (re-exportados no barrel):
   - `ClienteExterno` (`id`, `nome`, `productionType`)
   - `ProducaoExterna` (`id`, `nome`)
   - `ItemProducao` (`data`, `pacienteNome`, `atendimentoExternoId: string | null`,
     `codigoProcedimento`, `descricaoProcedimento`, `statusOrigem`, `viaAcesso: boolean`,
     `tipoAto`, `valorCobradoOrigem`, `valorPagoOrigem`) — arquitetura §3.2.
2. Novo `apps/web/src/server/integration/fin-api-client.ts` com
   `listarClientes()`, `listarProducoes(clienteExternoId)`, `buscarItens(producaoExternaId)`:
   - header `x-api-key` com `API_FINANCEIRO_KEY`; base `API_FINANCEIRO_URL`;
   - timeout 30s; retry ×3 com backoff exponencial **só** para 5xx/erro de rede;
   - `401` → `ApiError 502 FIN_API_401` imediato (sem retry); demais 4xx → `FIN_API_CLIENT`;
   - resposta não-array → `FIN_API_FORMATO`; **array vazio é caminho válido**.
3. Normalização defensiva no client: datas cortadas em 10 chars (`YYYY-MM-DD`), números via
   `Number.isFinite`, `via_acesso === "Sim"` → `true`, campo de atendimento
   (`senha`/`numero_atendimento`, quando a origem entregar) → `atendimentoExternoId`, ausente → `null`.
4. Env (`apps/web/src/lib/env.ts`): novas `API_FINANCEIRO_URL` (url, opcional),
   `API_FINANCEIRO_KEY` (opcional) e `FIN_API_SOURCE` (`'local' | 'http'`, default `'local'`).
   As variáveis antigas (`CARMEM_*`, `PROCEDIMENTOS_SOURCE`) **permanecem** até o cutover (5.5).
5. Modo `local`: fixtures novas em `fixtures-local.ts` servindo `ItemProducao`/`ClienteExterno`/
   `ProducaoExterna` (`registrarFixtureItens`, `registrarFixtureClientes`, `registrarFixtureProducoes`),
   sem remover as fixtures antigas (usadas pelo fluxo atual até a 5.5).
6. `npm run typecheck`, `lint` e `test` passam; suíte existente permanece verde.

## Complexidade e Riscos
- **Complexidade:** M (~3 pontos). Client isolado + tipos; sem UI, sem mudança de fluxo existente.
- **Escopo OUT:** sincronização (5.2), contagem (5.3), orchestrator/tela de execução (5.5),
  remoção do contrato presumido (5.5).
- **Riscos:** contrato da origem pode divergir da doc (`docs/integracao/api-financeiro-sistema-web.md`)
  — *mitigação:* normalização defensiva + erros tipados (`FIN_API_*`) fáceis de diagnosticar.
  `atendimentoExternoId` ainda não existe na origem — *mitigação:* nullable desde o dia 1 (§10.3).
- **DoD:** AC 1-6 + testes verdes + File List completa.
