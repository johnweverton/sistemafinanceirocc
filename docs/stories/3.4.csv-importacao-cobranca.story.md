# Story 3.4 — Importação CSV estendida com dados de cobrança

## Status
Ready for Review

## Story
**As a** operador,
**I want** importar médicos por CSV já trazendo os dados de cobrança (quando disponíveis),
**so that** o cadastro em lote deixe os médicos prontos para emissão sem retrabalho manual.

## Acceptance Criteria
1. `parseCsv`/`rowToInput` de `/api/medicos/importar` reconhecem as colunas de cobrança:
   `pagador_tipo`, `pagador_documento`, `pagador_nome`, `email`, `cep`, `logradouro`, `numero`,
   `complemento`, `bairro`, `cidade`, `uf`.
2. As colunas de cobrança são **opcionais**: linha sem elas importa o médico com cobrança vazia
   (comportamento atual preservado).
3. Se dados de cobrança forem fornecidos parcialmente/invalidamente, a linha é rejeitada com
   mensagem clara (linha + campo), sem abortar o lote (padrão atual de `erros[]`).
4. O modelo `public/templates/medicos-modelo.csv` é atualizado com as novas colunas e um exemplo
   preenchido e um sem cobrança.
5. Validação reusa `dadosCobrancaSchema` de 3.1 (documento por tipo, cep, uf, email).
6. Limites de segurança atuais (5 MB / 5000 linhas) permanecem.
7. `typecheck`, `lint`, `test` verdes.

## Complexidade e Riscos
- **Complexidade:** S (~2 pontos). Extensão pontual de parsing + modelo + testes.
- **Escopo OUT:** UI de cobrança (3.3); emissão (3.2).
- **Riscos:**
  - Vírgula em campos de endereço (ex.: complemento) quebra o `parseCsv` por split simples.
    *Mitigação:* decisão a registrar (orientar no modelo a evitar vírgula **ou** parser com aspas)
    — o dev escolhe o menor risco e documenta no Change Log.
- **DoD:** AC 1-7 + testes verdes + File List completa.
