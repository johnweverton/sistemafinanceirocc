# Story 8.3 — UI da conciliação (página Extrato) + saldo por empresa no dashboard

## Status
Done

## Story
**As a** coordenadora/equipe financeiro,
**I want** ver o extrato de cada empresa dentro do sistema — com as conciliações automáticas,
uma fila de sugestões para confirmar e as tarifas do período — e o saldo de cada conta no
dashboard,
**so that** eu não precise mais alternar para o app da Cora para saber o que entrou, de quem
e quanto sobrou.

## Contexto
Fecha o Épico 8. Backend pronto (8.1/8.2). Superfícies novas: página `/extrato` e cards de
saldo no `/dashboard`. Padrões de UI já existem: filtros/badges de Recebíveis, fila de
confirmação do matching de médicos (Épico 5), diálogos próprios (7.3).

## Acceptance Criteria
1. **Página `/extrato`** (menu na Sidebar, acesso admin/financeiro):
   - filtros: empresa (obrigatório, default MC), período, status de conciliação, tipo
     (crédito/débito/tarifa) — padrão visual dos filtros de Recebíveis;
   - lista com: data, descrição, contraparte (nome + documento), valor (crédito verde/débito
     vermelho), badge de status de conciliação; boleto vinculado (quando houver) com link;
   - **fila de sugestões** em destaque no topo: transação + boleto candidato lado a lado com
     ações **Confirmar** / **Vincular outro** / **Ignorar**;
   - ações por linha: conciliar manualmente (diálogo com busca de boleto pago da mesma conta),
     ignorar, desfazer — com estados de loading e toasts (padrão do projeto);
   - card de totais do período: recebido, saídas e **tarifas** (via totais do GET da 8.2);
   - botão **"Sincronizar extrato"** (por empresa) com resumo do resultado em toast e
     tratamento de `CONTA_NAO_CONFIGURADA` (mensagem clara, sem quebrar a página).
2. **Dashboard:** cards de **saldo por empresa** (MC / Cavalcante Viana) via rota nova
   `GET /api/contas/saldo` (admin/financeiro; cache em memória 60s por conta; conta sem
   credenciais → card "não configurada", nunca erro).
3. **Empty states**: sem sync ainda → orientação para sincronizar; período sem transações →
   EmptyState padrão.
4. Tema light/dark + acessibilidade no padrão do projeto (tokens, `role=alert`, aria nos
   filtros).
5. `npm run typecheck`, `lint` e `test` verdes; testes de componente: fila de sugestões
   (confirmar chama a rota certa), filtro por empresa, card de tarifas, saldo com conta não
   configurada.

## Complexidade e Riscos
- **Complexidade:** M (~3 pontos). Página nova, mas 100% sobre padrões existentes.
- **Escopo OUT:** DRE/categorização; cron; edição de transação (extrato é imutável — só o
  status de conciliação muda); Pix (adiado).
- **Riscos:** lista longa sem paginação — *mitigação:* paginação/virtualização simples desde
  o início (perPage 50 na UI) e filtros default por período curto (mês corrente).
- **DoD:** AC 1–5 + File List completa.

## Dev Agent Record

### Decisões de implementação
- **Filtro "Tarifas" é recorte de UI:** a API filtra `tipo=DEBIT` e o recorte
  `transactionType === 'FEE'` é client-side — a Cora classifica tarifa como débito e o GET
  da 8.2 já devolve `transactionType` cru.
- **Fila de sugestões sem boleto único:** quando a sugestão tem mais de um candidato
  (`boletoVinculado` null), o card orienta o vínculo manual em vez de esconder a ação.
- **Cache do saldo:** 60s por conta na rota (module-level, mesma técnica do cache de token
  do CoraHttpClient) + `staleTime` 60s no client. Degradação por conta: sem credenciais →
  `configurada: false` (card "não configurada"); consulta falhou → saldo null + `role=alert`;
  a rota nunca devolve erro HTTP por conta quebrada.
- **Desfazer avisa sobre re-sugestão** (OBS-821 do gate 8.2): toast orienta vincular o
  correto ou ignorar, senão o próximo sync pode propor o mesmo par.
- **Saldo no dashboard renderiza também no empty state** — saldo independe de haver boletos.
