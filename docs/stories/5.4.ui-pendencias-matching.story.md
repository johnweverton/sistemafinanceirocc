# Story 5.4 — UI: pendências de cadastro + sincronização com matching assistido

## Status
Done

## Story
**As a** operador do sistema de cobrança,
**I want** ver na tela de médicos quem está incompleto para cobrança e sincronizar com o sistema
web confirmando os pareamentos sugeridos,
**so that** eu complete os cadastros importados (CPF, especialidade, dados de cobrança) sem caçar
médico por médico, e nenhum vínculo seja criado sem a minha confirmação.

## Acceptance Criteria
1. Lista de médicos ganha **badge "incompleto"** e **filtro** correspondente. Critérios
   (arquitetura §6): `cpf` ausente · `especialidade` ausente · `!cobrancaCompleta(medico)` ·
   sem `externalId`. O badge/tooltip indica **quais** pendências o médico tem.
2. Botão **"Sincronizar com sistema web"** na tela de médicos → chama
   `POST /api/medicos/sincronizar` (5.2) e abre painel/modal com o relatório:
   - **Com sugestão:** cliente da origem + candidatas ordenadas por score, ações
     **Confirmar vínculo** (`POST /api/medicos/vincular`) e **Não é o mesmo** (move para "sem par");
   - **Sem par:** ação **Criar médico novo** (`POST /api/medicos/criar-externo`);
   - **Já vinculados/atualizados:** contagem informativa.
3. Feedback de sucesso/erro por ação (409 de vínculo duplicado exibido de forma amigável);
   lista de médicos refeteada após confirmar/criar.
4. `MedicoForm`: campo CPF passa a **opcional** ao salvar (validação de formato só quando
   preenchido); médico com `externalId` exibe o vínculo (read-only, ex. "Vinculado ao sistema
   web"). Pendências linkam para o form.
5. Estados vazios e de erro: API da origem fora do ar → mensagem clara no modal (sem quebrar a
   tela); nenhum médico pendente → estado vazio amigável.
6. `npm run typecheck`, `lint` e `test` passam; suíte existente permanece verde.

## Complexidade e Riscos
- **Complexidade:** M (~3 pontos). UI sobre rotas prontas (5.2); design system existente.
- **Escopo OUT:** tela de execução (5.5), CSV (inalterado), regras de matching (backend 5.2).
- **Riscos:** UX do matching confundir o operador — *mitigação:* score visível, ação destrutiva
  inexistente (rejeitar só move para "criar novo"), tudo reversível exceto o vínculo confirmado
  (aviso explícito antes de confirmar: "o vínculo é permanente").
- **DoD:** AC 1-6 + testes verdes + File List completa.
